From the overview, this model means we must move data through multiple different layers. It would be complicated to encode
each separate path, and so we must create a ```Matrix``` structure to hold our data are is travels through the layers.

Next, lets look at the class attributes, which is where we make our first optimisation. 

```cpp
struct Matrix {
    int rows;
    int columns;
    std::vector<double> row_values; //flat storage for cache optimisation
```

The point of interest is ```std::vector<double> row_values```. Thinking logically, we could opt for a different
structure, something much easier to visualise, something like ```std::vector<std::vector<double>> row_values```. This
makes things really simple, you can index by $$i$$ for row, and then index by $$j$$ to access values. So why do we choose a flat storage instead

Lets dip our toes into the world of memory optimisation. When you have a flat storage, you store the values in a contiguous block of memory, while
a vector of vectors allocates multiple separate blocks. The flat storage has many upsides, like cache efficiency and access speed. It does have some drawbacks, such as the
cost of resizing. 

The concept is challenging to get your head around, so here is a nice diagram to assist your understanding.

The next step is looking at constructors. For the first time, we use overloaded constructors. Lets view them.

```cpp
    Matrix() : rows(0), columns(0) {}

        
    explicit Matrix(int r, int c, std::vector<double> rv)
        : rows(r), columns(c), row_values(std::move(rv)) {
        if (row_values.size() != static_cast<std::size_t>(rows) * columns) {
            throw std::invalid_argument("Rows and columns does not match dimension size of input");
        }
    }

    // Zero matrix of a given shape.
    Matrix(int r, int c)
        : rows(r), columns(c), row_values(static_cast<std::size_t>(r) * c, 0.0) {}

    //weights matrix is randomly created, for the given size, 
    //mimicing the single neuron weights normal distribution method
    Matrix(int r, int c, std::mt19937& rng) : Matrix(r, c) {
        randomise(rng);
    }

    
    void randomise(std::mt19937& rng) {
        const double scale = 1.0 / std::sqrt(static_cast<double>(rows));
        std::normal_distribution<double> dist(0.0, scale);
        for (double& v : row_values){ 
            v = dist(rng);
        }
    }
};
```

That code concludes the ```Matrix``` struct: 4 constructors and 1 helper function. 
The matrix operations live outside the struct. The first one is ```matmul```, and is an overloaded function.
The first function returns a fresh ```Matrix``` object.

```cpp
inline Matrix matmul(const Matrix& A, const Matrix& B){
    //matrix A cross Matrix B

    if (A.columns != B.rows){
        throw std::invalid_argument("Columns of A must be equal to the rows of B");
    }
    const int m = A.rows;        // C is m x p
    const int n = A.columns;     // shared dimension (== B.rows)
    const int p = B.columns;

    std::vector<double> newValues(m * p, 0.0);   // zeroed: we ACCUMULATE into it

    for (int i = 0; i < m; ++i){
        for (int j = 0; j < n; ++j){
            const double a = A.row_values[i * n + j];
            for (int k = 0; k < p; ++k){
                newValues[i * p + k] += a * B.row_values[j * p + k];
            }
        }
    }
    return Matrix(m, p, newValues);
}
```
This is the perfect place to explain indexing with the flat storage structure. Firstly, observe the logic for indexing: we still have 2 for-loops to iterate in order,
when the vector is flat. Here is a nice diagram to explain what is going on, and to make sense of what the iterators do.

Lets look at ```void matmul```. The core difference is that we provide an output buffer, which can be persisted throughout a series of ```matmul```s 
to avoid creation and descruction of new ```Matrix``` objects, which is expensive, as you are hammering the heap allocator constantly
for buffers that are the same size.

```cpp
inline void matmul(const Matrix& A, const Matrix& B, Matrix& out) {
    // validate dimensions
    if (A.columns != B.rows){
        throw std::invalid_argument("Columns of A must be equal to the rows of B");
    }
    if (out.rows != A.rows || out.columns != B.columns){
        throw std::invalid_argument("Output buffer is wrong shape");
    }
    const int m = A.rows;        // C is m x p
    const int n = A.columns;     // shared dimension (== B.rows)
    const int p = B.columns;
    std::fill(out.row_values.begin(), out.row_values.end(), 0.0);  // zero it

    for (int i = 0; i < m; ++i){
        for (int j = 0; j < n; ++j) {
            const double a = A.row_values[i * n + j];
            for (int k = 0; k < p; ++k)
                out.row_values[i * p + k] += a * B.row_values[j * p + k];
        }
    }
}
```

Lets look at transpose next. 

```cpp
inline Matrix transpose(const Matrix &A){
    const int rows = A.rows;
    const int columns = A.columns;

    std::vector<double> newValues(rows * columns);

    for (int i = 0; i < rows; ++i){
        for (int j = 0; j < columns; ++j){
            newValues[j*rows + i] = A.row_values[i*columns + j];
        }
    }
    return Matrix(columns, rows, newValues);
}
```

Some more clues on how indexing works: ```(i,j)``` is ```(i*columns + j)``` and ```(j,i)``` is ```(j*rows + i)```.
Next lets look at matrix addition; adding the bias to all values. For completeness, we create two of the same function, one that mutates 
the first matrix in place, and the other that creates a fresh new ```Matrix```. 

```cpp
inline Matrix& element_wise_add_(Matrix &A, const Matrix &Bias){
    if (A.columns != Bias.columns){
        throw std::invalid_argument("Columns of A must be equal to the columns of the Bias Vector");
    }
    if (Bias.rows != 1){
        throw std::invalid_argument("Bias vector must only have 1 row");
    }
    const int rows = A.rows;
    const int columns = A.columns;
    for (int i = 0; i < rows; ++i){
        for (int j = 0; j < columns; ++j){
            A.row_values[i*columns + j] += Bias.row_values[j];
        }
    }
    return A;
}
inline Matrix element_wise_add(const Matrix &A, const Matrix &Bias){
    Matrix out = A;                       // copy
    element_wise_add_(out, Bias);         // mutate the copy
    return out;
}
```

inline Matrix& element_wise_subtract_(Matrix &A, const Matrix &B){
    if (A.rows != B.rows || A.columns != B.columns){
        throw std::invalid_argument("Matrix dimensions must be equal");
    }
    for (std::size_t i = 0; i < A.row_values.size(); ++i){
        A.row_values[i] -= B.row_values[i];
    }
    return A;
}
inline Matrix element_wise_subtract(const Matrix &A, const Matrix &B){

    element_wise_subtract_(out, B);
    return out;
}

Next the hadamard product, which is element-wise multiply, where both matrices are of the same shape.

```cpp
inline Matrix& hadamard_(Matrix &A, const Matrix &B){
    if (A.rows != B.rows || A.columns != B.columns){
        throw std::invalid_argument("Matrix dimensions must be equal");
    }
    for (std::size_t i = 0; i < A.row_values.size(); ++i){
        A.row_values[i] *= B.row_values[i];
    }
    return A;
}
inline Matrix hadamard(const Matrix &A, const Matrix &B){
    Matrix out = A;
    hadamard_(out, B);
    return out;
}
```

Next is scaling the numbers within the matrix. Very simple.

```cpp
inline Matrix& scale_(Matrix &A, double s){
    for (double& v : A.row_values) v *= s;
    return A;
}
inline Matrix scale(const Matrix &A, double s){
    Matrix out = A;
    scale_(out, s);
    return out;
}
```

And lastly, applying functions to all values in a function.

```cpp
template <typename F>
Matrix& apply_(Matrix &A, F f){
    for (double& v : A.row_values) v = f(v);
    return A;
}
template <typename F>
Matrix apply(const Matrix &A, F f){
    Matrix out = A;
    apply_(out, f);
    return out;
}
```

```template <typename F>``` allows us to take a function as a parameter to apply to the values in the matrix.
